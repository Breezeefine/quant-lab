# 个人量化操作系统 — 产品定义

版本：v1.0
日期：2026-05-31
状态：审查通过（已修正 3 项）

---

## 一、产品愿景

一个由 AI 驱动开发的个人量化操作系统，让量化新手能够从数据采集到策略回测到模拟实盘，完成完整的量化研究闭环。

**一句话定义**：用简洁的 DSL 表达式或 Python 代码定义策略，系统帮你回测验证它能不能赚钱。

**长期愿景**：未来支持用自然语言描述策略想法，AI 自动生成代码并回测。

---

## 二、目标用户

### 主要用户
- **个人投资者**：想用量化方法验证交易想法，但不懂编程
- **AI 原生开发者**：依赖 AI（Claude Code）编写代码，不追求手写每一行

### 非目标用户
- 高频交易团队（延迟要求 < 1ms）
- 多人协作的量化基金
- 需要复杂 GUI 操作的用户

---

## 三、用户场景

### 场景 1：验证一个策略想法
> 小明想验证"双均线金叉买入、死叉卖出"这个策略在 A 股上是否有效。
> 他打开系统，选择股票和时间范围，运行回测，看到收益曲线和夏普比率。
> 整个过程不超过 5 分钟。

### 场景 2：用表达式引擎快速定义因子
> 小明想测试"过去 20 日收益率排名前 10% 的股票"这个因子。
> 他在表达式编辑器中输入 `Rank(Return($close, 20), 20)`，系统自动计算并回测。
> 不需要写 Python 代码。

### 场景 3：模拟实盘验证
> 小明的回测策略表现不错，想看看在"真实"环境下效果如何。
> 他切换到模拟实盘模式，系统用实时行情（或最近 N 天数据）驱动策略运行，
> 模拟下单、持仓、手续费、T+1 等真实规则。

### 场景 4：查看绩效归因
> 小明想知道策略的亏损来自哪里。
> 他打开绩效分析页面，看到最大回撤时间段、胜率、盈亏比、单笔交易明细。
> 通过分析发现策略在震荡市亏损严重。

## 四、核心任务（MVP）

### 任务 1：数据采集与管理
- 从 AKShare 下载 A 股日线数据
- 存储为 Parquet 格式（按股票代码/年份分区）
- 在 Streamlit 中浏览数据、查看 K 线图

### 任务 2：表达式引擎
- 用 DSL 字符串定义因子（如 `Mean($close, 20)`）
- 系统解析 DSL → 编译为 Polars 表达式 → 向量化计算
- 支持 20 个核心运算符

### 任务 3：策略回测
- 编写策略（Python 类或 DSL 表达式）
- 选择股票池、时间范围、初始资金
- 运行回测，生成收益曲线和绩效指标
- 支持三种撮合模式：开盘价/收盘价/VWAP

#### DSL 策略信号规则
DSL 表达式定义的是因子值（如均线、排名等），需要配合信号规则生成交易指令：

**方式 A：阈值信号**
```yaml
factor: "Mean($close, 5) - Mean($close, 20)"   # 5日均线 - 20日均线
buy_when: "factor > 0"     # 短均线 > 长均线 → 买入
sell_when: "factor < 0"    # 短均线 < 长均线 → 卖出
```

**方式 B：排名信号**
```yaml
factor: "Rank(Return($close, 20), 20)"   # 20日收益率排名
buy_when: "factor > 0.9"   # 排名前 10% → 买入
sell_when: "factor < 0.5"  # 排名后 50% → 卖出
```

**方式 C：Python 类策略**（复杂策略）
```python
class DualMAStrategy(StrategyBase):
    def on_bar(self, bar):
        if short_ma > long_ma and no_position:
            self.buy(symbol, 100)
        elif short_ma < long_ma and has_position:
            self.sell(symbol, quantity)
```

### 任务 4：模拟实盘
- 使用统一引擎切换到模拟实盘模式
- 精确模拟 A 股规则（T+1、涨跌停、手续费）
- 实时查看持仓、资金、订单状态

### 任务 5：绩效分析与可视化
- Streamlit 仪表盘展示回测/模拟结果
- 核心指标：总收益率、年化收益率、夏普比率、最大回撤、Sortino 比率、胜率、盈亏比
- 收益曲线图、持仓明细、交易记录

## 五、MVP 闭环

```
[用户] → 选择股票和时间范围
         ↓
[系统] → AKShare 下载数据 → Parquet 存储
         ↓
[用户] → 定义策略（Python 类 或 DSL 表达式）
         ↓
[系统] → 表达式引擎计算因子 → 回测引擎执行
         ↓
[系统] → 撮合引擎模拟交易（A 股规则）
         ↓
[系统] → 绩效分析 → Streamlit 展示结果
         ↓
[用户] → 查看收益曲线、指标、交易记录
         ↓
[用户] → 切换到模拟实盘模式验证
```

**最短路径**：选择一只股票 → 使用默认双均线策略 → 点击运行 → 查看结果。预计 2 分钟内完成。

## 六、非目标（v1.0 明确不做）

| 不做 | 理由 |
|------|------|
| 实盘交易（券商对接） | MVP 阶段风险太高，先验证策略 |
| 多用户/权限系统 | 个人使用，无需 |
| 加密货币/美股支持 | 先聚焦 A 股，降低复杂度 |
| 分钟线/Tick 级回测 | 日线足够验证策略思路 |
| 机器学习/深度学习策略 | MVP 先做规则型策略 |
| 因子挖掘自动化（RD-Agent） | 后续阶段 |
| 移动端 UI | Streamlit 桌面端足够 |
| 数据实时推送（WebSocket） | 轮询模式足够个人使用 |

### 核心设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 回测引擎 | 自建（Polars 向量化） | 全代码可控，AI 友好 |
| 表达式引擎 | 自建（DSL→AST→Polars） | 移植 qlib 模式，~1000 行 |
| 数据接入 | vnpy Gateway 模式 | 抽象工厂 + 事件驱动 |
| 模拟实盘 | 统一引擎 | 回测/实盘共用策略代码 |
| 数据存储 | Parquet + DuckDB + SQLite | 零运维，文件级 |
| 前端 | Streamlit | 纯 Python，AI 生成准确率高 |
| 撮合模式 | 开盘价/收盘价/VWAP | 三种模式可配置 |
| 滑点模型 | 百分比滑点（默认 0.1%） | 简单有效 |
| 表达式运算符 | 20 个核心运算符 | 覆盖 80% 常用场景 |

## 九、A 股规则规格

### T+1 交易制度
- 买入当日冻结，次日转为可卖
- 卖出数量不得超过可卖数量

### 涨跌停限制
| 类型 | 涨幅 | 跌幅 |
|------|------|------|
| 主板 | +10% | -10% |
| 创业板/科创板 | +20% | -20% |
| ST 股 | +5% | -5% |

### 手续费
| 项目 | 费率 | 备注 |
|------|------|------|
| 佣金 | 万 2.5 | 买卖都收，最低 5 元 |
| 印花税 | 千 1 | 仅卖出 |
| 过户费 | 十万分之二 | 买卖都收 |

### 最小交易单位
| 市场 | 最小单位 |
|------|----------|
| 主板 | 100 股 |
| 科创板 | 200 股 |

## 十一、关键取舍

| 取舍 | 选择 | 放弃 | 理由 |
|------|------|------|------|
| 数据处理 | Polars | Pandas | 性能 10-100x，API 更适合 AI |
| 回测引擎 | 自建 | backtrader/rqalpha | 全代码可控，零学习成本 |
| 表达式引擎 | 自建 DSL | 纯 Python 代码 | 因子定义更简洁，可复用 |
| 前端 | Streamlit | React/Vue | 零前端知识，AI 生成效率高 |
| 数据存储 | Parquet+SQLite | PostgreSQL | 零运维，个人项目足够 |
| 撮合精度 | Bar 级别 | Tick 级别 | 日线策略足够，复杂度低 10 倍 |
