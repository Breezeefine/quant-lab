# research-check

## 触发条件

- 产品定义、开发计划、架构选择、实现方案、测试策略或上线流程需要参考成熟实践。
- 存在“不确定是否重复造轮子”的判断。
- 用户要求借鉴开源项目、官方文档或同类产品。

## 调研问题

先写清楚要回答的问题：

- 产品调研：别人怎么定义用户、边界、核心流程和差异化。
- 技术调研：成熟技术路线、架构、库、约束和维护风险。
- Agent 调研：工具官方配置方式、skills/subagents/commands/hooks 等可吸收模式。
- 验证调研：行业里常用的测试、评审、上线和回滚做法。

## 调研执行

- 优先使用官方文档、项目 README、公开源码、成熟案例和可验证资料。
- 记录资料时间和适用范围；过时、不确定或不可验证的内容要标注。
- 不复制外部方案；只吸收适合 Foundry 闭环的机制。

## 可复用结论

每条调研结论都要落成可用格式：

- 结论是什么。
- 证据来自哪里。
- 对当前阶段有什么影响。
- 是否进入 Product.md、DevPlan.md、Memory.md 或 Feedback.md。

## 输出要求

更新 Research.md；必要时在 docs/research/ 下写独立调研文档；同步 WorkingContext.md 的最近调研摘要和下一步。
