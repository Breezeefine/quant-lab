# tdd-development

## 触发条件

- 新功能、bug 修复、重构或行为变更。
- 当前切片有明确验收故事。
- 可以用自动化测试或脚本验证目标行为。

## RED

- 先写一个最小失败测试，表达期望行为。
- 运行测试，确认失败原因是功能缺失或 bug 存在，不是测试写错。
- 记录失败命令和关键输出。

## GREEN

- 只写让测试通过的最小实现。
- 不顺手加入计划外能力。
- 测试不过时修实现，不随意降低测试要求。

## REFACTOR

- 测试通过后再整理命名、重复代码和结构。
- 每次重构后重新运行相关测试。
- 如果发现新行为需求，回到 RED 新增测试。

## Foundry 记录

- Progress.md 记录 RED/GREEN/REFACTOR 的验证命令。
- WorkingContext.md 记录当前切片状态和下一步。
- 若发现长期规则，写入 Reflection.md 或 Memory.md。

## 输出要求

返回失败测试证据、通过测试证据、变更文件、未覆盖风险和下一步。
